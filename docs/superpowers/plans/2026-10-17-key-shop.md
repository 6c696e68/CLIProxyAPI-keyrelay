# Key Shop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `key-shop` plugin that issues expiring, token-capped client keys and a public page at `/key-dashboard`.

**Architecture:** Policy and SQLite live in a CGO-free `keyshop` package. `package main` adapts the CPA plugin ABI. The host only aliases two public GET routes onto plugin resources.

**Tech Stack:** Go 1.26, `modernc.org/sqlite`, CPA plugin ABI schema 6, Gin host alias.

**Spec:** `docs/superpowers/specs/2026-10-17-key-shop-design.md`

## Global Constraints

- Plugin ID and shared-library stem are `key-shop`.
- Module path is `github.com/router-for-me/CLIProxyAPI/v8/examples/plugin/key-shop/go`.
- Replace that module with `../../../..` is not required. The core package must not import the host.
- Customer secret prefix is `ck_`. Principal and logs use the key id, never the secret.
- Default TTL is `168h`. Default token limit is `100000000`. Explicit `0` means unlimited.
- Billed tokens are `input_tokens + output_tokens`. Failed requests bill `0`.
- Reserve default is `32768`. Reservation TTL is `15m`. Request retention is `30` days.
- Public paths are `/key-dashboard` and `/key-dashboard/api/session`.
- Management paths contain no `:`.
- Do not edit `/v0/management` handlers except to compile.
- Do not copy AGPL code. Do not deploy. Do not touch live `config.yaml` or `auth/`.
- No `time.Sleep` in tests. Inject `now`.
- `gofmt` every Go file. Comments in English.

- [ ] **Step 3: Write minimal implementation**

Parse the host envelope whether the payload is raw or wrapped in `result`. On `usage.handle`, stash tokens by `RequestID` using the exported Go field names. On `request.complete`, call `Finalize`. A native key that does not start with `ck_` is not handled and is not terminated. `frontend_auth.authenticate` rejects expired, disabled, exhausted, and unsupported-path `ck_` keys. Paths include `/v1/live`, `/v1/live/side`, `/v1/realtime`, `/v1/realtime/calls`, `/v1/alpha/search`, and `/backend-api/codex/alpha/search`. `request.intercept_before` returns 403 or 402 for expired, disabled, and exhausted keys, including count-token and `generate=false` requests. A store error on a `ck_` key returns an OK envelope with `Terminate: true` and status `503`. It must not return a plugin error.
